Four environments, two world-model algorithms, one workstation.

Overview

World models learn to predict their environment and let an agent plan or learn behavior inside the learned simulation. This project reproduces two influential world-model approaches end to end — setting up the environments, fixing the training infrastructure, and running them to convergence on a single workstation (2× RTX 4090, 61 GB RAM).

DreamerV3 is a general model-based RL agent (JAX) that learns a recurrent latent world model and trains an actor-critic entirely in imagination. I reproduce it on Minecraft (Diamond) via MineRL and on ProcGen CoinRun. LeWM is a JEPA-style latent world model that predicts future representations rather than pixels; I reproduce it on the Cube manipulation and PushT control tasks. For every task the page shows how rollouts improve across training epochs.

Cube Manipulation

A JEPA latent world model trained on the Cube manipulation dataset (OGBench cube_single): it predicts future latent states of a robot rearranging cubes. PushT

PushT is a 2D contact-rich control task (pymunk/pygame) where an agent pushes a T-shaped block to a target pose. The world model is trained on expert trajectories and evaluated by rolling out planned actions. DreamerV3 · JAX

Minecraft — Diamond

A 200M-parameter DreamerV3 agent trained on MineRL's minecraft_diamond, the 12-milestone curriculum from logs to diamond. Running this headless on a single 4090 required Java 8 + xvfb, a pinned numpy/JAX stack, a 64 GB swapfile with a capped replay buffer, and an hourly replay-chunk cleaner. The agent reached the iron tier (score ≈ 10) at ~2.3M environment steps (~3.4M steps/day at 4 envs). The clips compare the agent's behavior at increasing training steps.

Engineering Highlights

  • Stabilized large RL/world-model training on a single workstation (2× RTX 4090, 61 GB RAM) — ran a 200M DreamerV3 model and a JEPA world model to convergence, including two trainings in parallel pinned across GPUs.
  • Root-caused a flaky XLA GPU compile-time autotuning segfault that hit ~50% of Minecraft launches. Isolated it with a controlled experiment (same graph, no Minecraft) and fixed it via XLA flags (xla_gpu_autotune_level=0, disabled preallocation) — 6/6 clean launches vs. a ~50% baseline.
  • Memory & disk engineering for unbounded replay. Added a 64 GB swapfile, capped the replay buffer, and wrote an hourly replay-chunk cleaner to bound disk growth (~18 GB per 1M steps), keeping long Minecraft runs stable at ~45 fps with near-zero iowait.
  • Diagnosed a dataloader OOM in LeWM caused by an end-of-epoch validation worker pool spiking the working set; tuned worker count and persistence to remove the thrash.
  • Data-pipeline throughput. Converted HDF5 datasets to Lance for GPU-bound reads, cutting Cube epoch time from ~67 to ~55 min and saturating the GPU.
  • Headless, reproducible environments. MineRL via Java 8 + xvfb with a pinned numpy/JAX stack; ProcGen and PushT set up from source; live agent-view monitoring served over HTTP.
